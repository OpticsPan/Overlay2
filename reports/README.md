## 后续PDF报告的中文学术论文排版要求

来源：2026-10-28用户明确要求后续PDF参考中文学术论文的国标格式，行两端对齐、段首缩进两个空格等。此要求适用于后续新写及修订交付的研究报告PDF；本次记录规范，不据此宣称既有R1已经完成重排。

- **标准依据：** 参考GB/T 7713.2《学术论文编写规则》组织论文，参考GB/T 7714《信息与文献 参考文献著录规则》组织引文和参考文献；每次正式排版前核对现行、适用版本并记录所采用版本。用户或交付单位另有明确模板时，记录适用要求及差异。未经逐项核对，不宣称报告全面符合国标。
- **正文对齐：** 普通正文段落采用两端对齐，段落末行自然左对齐，不强制把末行拉满。
- **首行缩进：** 普通正文每段首行缩进两个汉字宽度（两字符，通常为`2em`）。用户所说“两个空格”按中文排版的两个汉字宽度落实，不以两个半角空格代替；通过段落样式设置，不在Markdown中用空格或制表符拼版。
- **独立版式元素：** 标题、封面信息、目录、图题、表题、表内文字、公式、列表、参考文献条目按相应元素的版式处理，不机械套用正文首行缩进。图表题及图表应对应，参考文献缩进方式与选用的著录格式一致。
- **结构与编号：** 按报告性质配置题名、摘要、关键词、正文层次、结论、参考文献及必要附录；较长报告设置目录。章节、图、表、公式及引用编号统一、连续、可追溯。
- **字体与页面：** 全文统一中文正文与标题字体、字号、行距、段前段后间距、页边距和页码；具体参数记录在模板或交付说明中。标准未明确规定的参数作为仓库或任务排版选择，不杜撰为国标强制值。中文字体应正确嵌入PDF，符号及上下标清晰。
- **图表与分页：** 保持原专利图可辨认、比例正确，附来源公开号、原图号和物理页；图题与图、表题与表尽量同页，跨页表重复表头，避免标题落在页底、文字溢出或图片遮挡正文。
- **交付检查：** 导出后目视抽查正文首行缩进、两端对齐、目录、图表、公式、引文和页码，并检查中文可复制/检索及MD/PDF内容一致性；记录实际检查页和结果，不能仅凭导出成功认定版式合格。

后续更新[排版模板](templates/report.css)或更换PDF工具时，必须落实并验证上述要求。现有模板尚未设置正文首行`2em`缩进，不能直接作为已满足新要求的证据；下次用户要求生成或修订PDF时应先调整模板并检查输出。

## 流程框图美观要求

来源：2026-10-28用户明确要求“绘制流程框图的时候，一定要美观”。此项是后续绘制和修改自绘流程框图的必检要求，与技术准确、文字完整和可读性同时满足。

- **布局整齐：** 主流程方向统一，层级和分组清楚；同层节点对齐，同类节点的尺寸、间距及内边距协调，整体留白均衡，避免局部拥挤或无意义的大面积空白。
- **视觉统一：** 字体、字号层级、边框、圆角、线宽和箭头风格统一；节点尺寸兼顾整齐与文字容量，不能为追求等宽等高而裁切文字。
- **配色克制：** 采用少量协调颜色表达层级或功能，文字与背景保持足够对比度；同一颜色含义一致，必要时添加图例，黑白打印时仍能通过文字或线型辨认关系。
- **连线清晰：** 优先采用简洁、规则的连线路径，减少交叉、折返和不必要的弯曲；反馈路径尽量沿主流程外围布置，标签靠近对应连线且不遮挡节点、箭头或其他文字。
- **信息适量：** 节点使用简洁标题和必要说明，长内容合理换行，复杂图拆分为总图与局部图；保持原有技术含义和关系可追溯，不为美化省略关键逻辑。
- **实际效果验收：** 在最终展示尺寸下目视检查整体美观、对齐、间距、配色、连线及文字可读性，发现拥挤、失衡或风格混杂须调整后再交付；保留预览或检查记录。自动布局和导出成功不能代替视觉审阅。

## 框图文字完整性要求

来源：2026-10-28用户指出框图方框太小或文字太大，导致节点文字显示不全，要求修复。此要求适用于后续报告、结构说明中的自绘框图。

- **尺寸随内容调整：** 根据实际字体度量、行数和内边距确定节点宽高，不用固定小方框容纳长文字。长说明按语义分行；优先扩大节点或拆分图，不以持续缩小字体解决拥挤。
- **显示稳定：** 使用支持中文的字体，字体加载完成后再布局。跨平台发布优先使用经检查的SVG；必要时将字形转为矢量轮廓，并同时保留可编辑文字源文件及正文解释。不得裁剪文字、用省略号隐藏内容或让连线穿过文字。
- **交付验证：** 逐一检查全部节点和箭头标签，确认文字完整、边距充足、无重叠；在实际Markdown显示宽度和最终PDF页面尺寸分别检查可读性。完整显示与字号可读是两项独立要求，不能仅凭生成命令成功认定合格。未生成PDF时明确该检查尚未执行。
- **专利原图：** 上述布局调整只针对自绘图；原专利图保持原件内容，需要解释时另绘并标注重绘及来源。

当前[L0—L4框图](figures/l0-l4-structure.svg)由[Graphviz源文件](figures/l0-l4-structure.dot)生成。环境使用Graphviz 2.42.4、Noto Sans CJK SC；节点16pt、边标签13pt、自动尺寸及显式换行是本图的排版选择，不是国标强制值。仓库根目录重建命令：

```bash
dot -Tsvg:cairo reports/figures/l0-l4-structure.dot -o reports/figures/l0-l4-structure.svg
```

使用Cairo后端保存字形轮廓，避免浏览器字体替换改变文字占用空间；更新源文件后必须重建并目视检查SVG。图中技术含义的正确性仍需单独核验。

## 继承与修订

1. 未明确要求从零撰写时，先复制适用旧报告的Markdown。新主题使用新目录；同一报告修订通过Git保存旧版。若无适用旧报告，记录新建理由。
2. 记录父报告路径、父报告提交或哈希、资料基线与本次范围。复制不等于重新验证。
3. 重新检查题名、摘要、适用对象、图表编号、相对引用路径、权利要求版本、数字、公式、结论与外推标记。删除不适用于新主题的旧内容。
4. 每项关键判断定位至公开号、原PDF物理页、图号及段落/权利要求；关键公式与权利要求回看原件。来源PDF与机器全文保持原字节。
5. 同步来源清单、REQ、CHANGELOG、状态和交付记录。仅在用户要求PDF时生成/更新PDF；未更新时明确PDF过期，不声称与新MD一致。
6. 执行现有仓库测试和基线校验；检查PDF文字、图片、表格、公式与分页，再进行内容审阅。未运行的远端CI不得标为通过。

## PDF生成

构建脚本为[build_report.py](build_report.py)，样式为[report.css](templates/report.css)。当前脚本面向本报告，其他报告可据此调整输入路径。使用Pandoc生成HTML、Matplotlib将数学公式排版为SVG、WeasyPrint导出PDF；需要Noto Serif/Sans CJK SC中文字体以及WeasyPrint系统字体/排版依赖。

本次环境：系统Python提供Matplotlib，独立工具环境`/workspace/report-tools`提供WeasyPrint 68.1。在仓库根目录执行：

```bash
python3 reports/build_report.py --weasyprint /workspace/report-tools/bin/weasyprint
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/validate_repository.py --base dd7ee03acec72b6db251f59b2bcf798aa1ff2aed
```

上面的SHA只适用于R1任务；后续用各自真实变更前基线。工具路径是本次环境示例，不要求其他机器采用相同目录。构建不下载专利、不修改原始资料。公式SVG只用于排版，Markdown中的公式是文字源；数学图形需目视核查。来源图片引用仓库现有文件，单独分发Markdown时需一并提供这些相对路径的图像。
