# 资料维护规则

日期：2026-11-09 · [资料目录](../references/patents/README.md) · [需求](REQUIREMENTS.md) · [维护状态](STATUS.md)

## 来源与目录

- 以明确公开号及种类代码标识专利版本；同族不同公开号分别登记。
- `references/patents/<公开号>/original.pdf`保存原件；`mineru.md`保存原语言机器全文；`figures/`保存正文引用图像。
- [manifest.json](../references/patents/manifest.json)是专利资料文件、页数和SHA-256的唯一机器清单；首页数字是带日期的摘要，更新清单时同步摘要。
- 参考资料是正式版本内容；本机下载、模型、缓存、转换中间输出和环境不进入仓库。

## Markdown转换后的默认仓库备份

用户于2026-11-09明确要求：每次完成Markdown转换，总是上传仓库备份。这是持续授权，后续任务无需逐次询问；用户明确要求仅本地或不上传时，以当次要求为准。

1. 转换完成后，将Markdown、全部图片依赖、原件来源与哈希、工具版本／参数及质量记录整理入库。原PDF尚未入库时一起备份；已有原件不重复复制、不改路径或字节。
2. 论文进入`references/papers/<稳定标识>/`，使用`mineru.md`、`images/`、`conversion.json`及`QUALITY.md`；独立[论文清单](../references/papers/manifest.json)登记实际页数及各文件哈希。清单`original_pdf`和`artifacts`路径相对仓库根，`markdown`路径相对论文目录根。
3. 为保留历史链接，已经放在其他`references/`位置的原PDF可由论文清单引用；不把论文计入专利统计。新论文原件应放在其论文目录中。
4. 检查完整页序、图像依赖、相对链接和代表页；同步目录、Unreleased、需求与维护状态，并在main首页的[结果直达区](../README.md#latest-results)增加本次全文直达链接，批量转换可链接到有逐项入口的索引。模型、环境、缓存、运行日志及不需交付的分析中间文件留在本地D盘。
5. 按短期分支与PR流程上传，经自审及对应检查后合并；回读远端main的文件哈希及Actions结果，并在交付中提供全文和提交／PR链接。上传或检查未完成时标明待备份／待核验，不报告备份完成。

## 新资料入库

1. 先查清单避免重复，核对原件首页的公开号、题名、语言和页数，记录来源URL或用户提供事实。
2. 将原件归集到D盘工作区并计算SHA-256；保持原始字节。无原件时明确留缺，不用HTML、译文或同族版本冒充。
3. 使用MinerU转换，保留原语言，逐页建立`p0001`等锚点及`original.pdf#page=1`链接；图像依赖一同保存。资源允许时并行，每件独立输出并验证完整页序。
4. 在清单中登记实际页数、文件路径、每个资料文件的字节数与SHA-256、转换方式及来源；数量由实际清单推导。
5. 核对代表页的文字、权利要求、图纸和公式；把发现的问题单独记录到QUALITY。关键研究引用仍须核对PDF。
6. 更新资料目录、main首页结果直达入口、Unreleased和相关需求证据，执行下述检查，通过PR审阅后入库；合并后回读首页及链接目标。

## 原件和修订

- 已有原件不得直接覆盖、删除或改名；相对Git基线的原件改写会被自动检查拒绝，即使清单哈希也同时改写。
- 不同公开号使用新目录。同一公开号确需修正原件时，先明确授权、来源差异及保留旧字节的版本方案，再调整清单结构与校验规则；不要通过改哈希规避保护。
- 修改页眉、链接或校核说明时保持机器正文可追溯，并更新受影响文件哈希。重新转换须记录工具版本、来源哈希、旧提交及差异，保留Git历史；不悄悄把人工修订当成机器原文。
- 不自动重建报告PDF；仅在用户明确要求时生成或更新。

## 验收命令与检查边界

```bash
python -m pip install -r requirements-validation.txt
python -m unittest discover -s tests -v
python tools/validate_repository.py --base <变更前提交SHA>
```

| 检查 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 原件／派生文件SHA-256及字节数 | 文件与登记值相符 | 原件真实性、文字准确率 |
| 实际PDF页数和完整有序锚点 | 全部物理页有对应入口 | 每页内容提取完整、阅读顺序正确 |
| 图片数量、清单覆盖、相对链接和页目标 | 文件可追溯且链接可解析 | 图中箭头、表格或公式语义正确 |
| Git基线原件保护 | 已有原件未被直接改写／删除 | GitHub分支保护已启用 |
| 单元测试 | 已覆盖的异常能够被检出 | 未测试输入不存在问题 |

GitHub Actions对PR、main推送和手动运行执行相同检查。PR采用目标分支SHA，push采用变更前SHA；手动运行需提供基线SHA，完整结果可从工作流中查阅。

专利转换限制见[专利QUALITY.md](../references/patents/QUALITY.md)，论文限制见各论文目录内的QUALITY.md，不得仅因为CI通过而移除已知问题。校验器分别统计专利和论文，检查两类清单、源文件哈希、完整页序、图像数量及依赖，并保护`references/`下既有PDF不被改写、删除或改名；其他资料类型须另行补充清单和验收范围。
